# Схема файлу треку

Кожен `src/track_*.js` містить один об'єкт `TRACKS.<ключ> = { … }`. Ключі: `pm`, `an`, `law`. Двигун `engine.js` бере активний трек і будує з нього всі екрани. Новий трек = новий файл за цією схемою + рядок у `build.py`.

## Загальне

| Поле | Тип | Де видно |
| --- | --- | --- |
| who, what, short, doc | рядки | картка вибору треку, заголовки |
| skill, arg | рядок | назва навички (`/zvit`) і приклад аргументу |
| folder, dataFolder, outFolder | рядки | шапка агента, дерево файлів |
| how | 4 рядки | опис задачі на кожній сходинці (етап 1) |

## Симулятор (етап 2)

| Поле | Формат | Примітка |
| --- | --- | --- |
| simIntro, request | рядки | умова задачі й запит |
| chat | [кнопка, тип, текст користувача, відповідь чату, лічильник?] | тип: 0 запит, 1 вставка, 2 репліка, 3 завершення; у відповіді `<mark class='unv'>` для неперевірених тверджень |
| agent | [think/act/check/ask/permit, підпис, html, (для ask) [2 варіанти]] | |
| chips | масив підрядків | назви файлів, що підсвічуються, коли трапляються в кроці агента |
| done(a) | функція | підсумок агента; a = індекс обраного варіанта в ask |
| reveal | [твердження чату, як насправді, хто помітив] | один рядок на кожну червону позначку |
| chain | 4–6 рядків | ланцюжок перевірки, останній = виправлений результат |
| why | 3 рядки | приклади до карток «Не бачить файлів / Не перевіряє / Забуває правила» |
| nextTitle, nextChat, nextCmd | рядки | блок «наступного разу» |

## Як влаштований агент (етап 3)

| Поле | Формат |
| --- | --- |
| predict | 3 × {node 0–3, q, o[3], a, why} |
| files | { шлях: [підпис, html вмісту] }, рівно три файли: CLAUDE.md, SKILL.md, скрипт |

## Правила й навичка (етап 4)

| Поле | Формат | Примітка |
| --- | --- | --- |
| ann | [заголовок, пояснення] на кожен `##` розділ CLAUDE.md | у тому ж порядку, останній «Чого не робити» |
| noDo | 4 × [текст, потрібен?, чому] | рівно 2 потрібні, текст до 70 символів |
| noDoFb | рядок | повідомлення про успіх |
| l3title, l3 | 3 × [заголовок, 3 варіанти, індекс правильного] | інша задача того ж треку |
| l4placeholder, chk, out(f) | | чекліст з 5 регулярних виразів; out повертає [без правил, з правилами] |
| steps, stepsHint | 6 кроків у правильному порядку | двигун перемішує їх сам |
| badScript, goodScript, runOk, runFile(a) | | навмисна помилка в навичці і її виправлення |

## Судження (етап 5)

| Поле | Формат |
| --- | --- |
| judge | 8 × [задача, кошик 0 агент / 1 агент готує, вирішує людина / 2 лише людина, пояснення] |
| draftSrc | інструкція до вправи |
| draftFacts | 3–5 фактів, кожен починається з назви джерела |
| draft | 6 × [речення, помилка 0/1, пояснення]; рівно 2 помилки, кожна перевіряється одним фактом |
| draftDone | урок одним реченням |

## Старт (етап 7)

| Поле | Формат |
| --- | --- |
| bPrompts | 6 × [заголовок, опис html, запит]; перший генерує навчальну папку з тими самими пастками, останній = команда навички |
| warn | html попередження перед роботою зі справжніми файлами |
| gen, genClaude(g), genSkill(g) | поля форми й шаблони власних CLAUDE.md і SKILL.md |
| plan | 8 рядків: 4 тижні × (назва, текст) |

Задачі для анатомії задачі (TASKS) і тексти макетів застосунку зараз живуть у `engine.js`.
